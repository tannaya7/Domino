## Tagline (94/100 chars)

> See what breaks before it breaks: map hidden shared-fate risk across your third-party vendors.

## Description (≤150 words)

> A dependency list tells you *what* you depend on — not that four "independent" vendors secretly
> share one substrate, so one AWS regional outage takes all four down together. Blast Radius Mapper:
> paste a GitHub repo, and it walks the real JS/TS import graph, detects vendors from
> imports/env vars/manifests/IaC, and groups them by shared hosting substrate. On the showcase repo
> alone, 5 vendors collapse into just 2 independent substrates — 80% sharing one. It then runs an
> exact correlated-failure model (cross-validated against a seeded Monte Carlo oracle) to quantify
> expected downtime and financial exposure under editable assumptions — never a guess dressed up as
> a number. A PR Resilience Gate (GitHub Action) comments on every PR with the new shared-fate risk
> it introduces and can fail the check against a policy you own. Every AI output is labeled; every
> unreachable status reports "unknown," never a fabricated "healthy."

## Challenges we ran into

- **Correlated risk is easy to get wrong in a way that looks right.** An early version fabricated
  correlation risk for vendors on substrates with only one vendor on them — fixed in commit
  `6722d43`, and now caught structurally: `src/engine/correlated.test.ts` cross-validates the exact
  model against an independently-implemented Monte Carlo oracle, so the two have to agree.
- **No AWS account was available while building the AWS integration.** Every Bedrock/DynamoDB/AWS
  Health/SNS path is written to the real, documented service contract and covered by mocked-SDK
  tests — but that's a different claim from "verified live," and
  [docs/AWS_VERIFICATION.md](AWS_VERIFICATION.md) says so explicitly rather than blurring the two.
  For this submission specifically, the live demo URL runs on a Cloudflare-tunneled local backend
  instead of a real AWS deployment, for the same reason.
- **A tunnel is not a deployment.** The first Cloudflare/loca.lt tunnel behind the PR Resilience
  Gate proof degraded to failures within ~15 minutes of a clean start, even though the local server
  behind it stayed healthy — solved with a watchdog (`scripts/tunnel-watchdog.sh`,
  `scripts/live-demo-watchdog.sh`) that health-checks, restarts, and re-points dependent config
  automatically, not by pretending the underlying instability doesn't exist.
